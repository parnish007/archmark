# Verification — what was actually tested

This is a curated evidence ledger, not raw research. Every claim below names what was
tested, which public asset or command it concerns, and what PASS means.

## Core CI — PASS

Workflow: `.github/workflows/ci.yml` (Ubuntu + Windows, Node 24), runs on every `main` push.

| Step | What PASS means |
|---|---|
| `pnpm install --frozen-lockfile` | Reproducible dependency install, no lockfile drift |
| `pnpm typecheck` | `tsc --noEmit` clean |
| `pnpm exec biome lint src tests scripts` | No lint findings |
| `pnpm exec biome format src tests scripts` | Formatting stable (would fail on drift) |
| `pnpm test` | Full suite green (126+ tests, see below) |
| `pnpm build` | `tsc` emits `dist/` incl. CLI entry with `#!/usr/bin/env node` |
| `archmark build/check README.md` | Root showcase diagram fresh |
| `archmark build/check examples/hero/README.md` | Hero static + animated assets fresh |
| `npm pack --dry-run` | Package metadata clean, no normalization warnings |

Latest `main` runs are green on both platforms — see the repo Actions tab.

## Test suite — PASS

`pnpm test` (vitest): parser, compiler diagnostics, ELK layout incl. adversarial group
truthfulness, markdown scanner/regions/patcher, ownership + fail-closed patching, security
(escaping, symlinks, caps), animation compiler (Flow → Timeline → Animation IR), SVG
structural validity (well-formed XML, resolving refs), CLI safety, and the icon-family
completeness invariant (`tests/renderer/icons.test.ts`: every `NodeKind` has an explicit
icon — adding a kind without one fails the build).

## Production GitHub rendering — PASS

- Root static assets (`archmark.light.svg` / `archmark.dark.svg`, generated by
  `archmark build README.md`) served through `github.com/.../raw/main` → 302 →
  `raw.githubusercontent.com` with HTTP 200 and `image/svg+xml`. PASS means the exact
  bytes a visitor's browser receives render as the intended diagram.
- Production animated hero (`examples/hero/archmark.hero.request.light/dark.svg`,
  generated by `archmark build examples/hero/README.md`) delivered through the same GitHub
  path and observed animating. PASS means motion plays and the asset settles on its final
  frame. The asset is generated, checked for freshness in CI, and contains no JavaScript
  (SMIL only — no `<script>`, verified by inspection).

## Browser matrix — PASS

Script: `scripts/generated-matrix.js` (hermetic: builds fixtures in a temp dir with the
current checkout's CLI, then samples live animated values — PASS requires observed value
change over time, no pixel heuristics). Workflow: `.github/workflows/browser-compat.yml`
(manual or weekly, non-blocking by design — animation compatibility is observed evidence,
not a merge gate).

| Engine | Result |
|---|---|
| Chromium | PASS — motion sampled during animation and after freeze |
| Firefox | PASS — motion sampled during animation and after freeze |
| Playwright WebKit | PASS — motion sampled during animation and after freeze |

## Theme behavior — PASS

- `<picture>` `prefers-color-scheme` selection verified live: correct light/dark variant
  served per scheme for root static, hero static, hero animated, and icon gallery assets.
- Static fallback: the first frame of every animated asset is a complete, correct diagram
  (viewers with animation disabled still see the architecture).

## Animation properties — verified by construction + inspection

- Finite then freeze: every timed element uses `fill="freeze"`; nothing loops forever.
- No JavaScript: animated assets contain only SMIL (`set` / `animate` / `animateMotion` /
  `mpath`); zero `<script>` elements, zero event-handler attributes.
- Production-generated: the README hero is byte-identical to CLI output
  (`archmark build` + `check` green in CI), never hand-authored.
